# 🎓 Pédagogie Active — N1 / N2 / N3

> Ce document définit la **philosophie d'apprentissage par la pratique** de Solicode, structurée en 3 niveaux de progression.

---

## 1. La Double Compétence (Modèle Hybride 2TUP)

Notre pédagogie sépare l'acquisition technique de la mise en situation professionnelle :

1.  **Le Socle Technique (N1 / N2 / N3) :**
    *   *But :* Apprendre les bases et construire le Projet Technique.
    *   *Mode :* **Individuel (EFM)**.
    *   *Progression :* Imiter -> Adapter -> Transposer (Projet Technique Final).

2.  **La Réalisation Professionnelle (Sprints) :**
    *   *But :* Appliquer la technique dans une situation réelle (le Projet file rouge) et développer les compétences transversales (Soft Skills).
    *   *Mode :* **Groupe (Agile/Scrum)**.
    *   *Progression :* Branche Fonctionnelle -> Livraison Application Finale.

---

## 2. Les 3 Niveaux d'Apprentissage

### 🟢 N1 — Imiter (Le Socle)
*   **Concept :** "J'apprends les bases."
*   **Méthode :** Tutoriels pas-à-pas sur des exemples du Projet technique.
*   **Objectif :** Acquérir les **bases (strict minimum)** de chaque compétence. L'apprenant doit comprendre suffisamment le code pour être capable ensuite de faire des recherches et d'adapter l'existant.
*   **Livrable :** Le projet-technique-n1: le résultat de réalisation de tous les tutoriels qui sont par défaut de niveau n1.

### 🟪 N2 — Adapter (Le Projet technique N2)
*   **Concept :** "Je prépare le Projet Technique N3 et je valide mes acquis."
*   **Méthode :**
    *   **Adaptation :** Enrichir le code du N1 par la recherche personnelle.
    *   **Live Coding (Évaluation) :** L'apprenant réalise une fonctionnalité ou une modification en direct devant le formateur.
    *   Réalisation des labs : un lab est atelier pratique préparer par l'apprenant pour aider les autre apprenant à réaliser une fonctionnalité. prévue dans la réalisation de projet.
*   **Objectifs :**
    1.  **Minimiser le risque** d'échec au Projet Technique N3 en sécurisant les techniques clés maintenant.
    2.  **Valider la compréhension ("Audit") :** Prouver que l'apprenant maîtrise ce qu'il a imité en N1, sans dépendre de l'IA ou du copier-coller. Cela sert de base à la notation des compétences.
*   **Livrable :** Le Projet Technique-n2 + Note individuelle de Live Coding.

### 🟧 N3 — Transposer (Le Projet Technique / 2TUP)
*   **Concept :** "Je finalise le Socle Technique."
*   **Méthode Hybride (2TUP) :**
    *   **Branche Technique (Individuel) :** Finalisation du prototype générique complet (Sécurité, Architecture avancée).
*   **Objectif :** Réaliser le **Prototype Technique de 2TUP** en sa version finale.
*   **Livrable :** Le Projet Technique (Socle Final)

---

## 3. Types de Ressources Associées

### 🟢 N1 — Tutoriel Pas-à-Pas
*   **Exemple :** "Créer ta première route Laravel et afficher une vue Blade."

### 🟪 N2 — Exercice d'Adaptation
*   **Exemple :** "À partir du code précédent, ajoute une colonne 'Auteur' à la table Article."

### 🟧 N3 (Projet Technique) — Conception générique
*   **Exemple :** Chaque apprenant a son propre projet technique, mais tous les projets sont identiques.

---

## 4. Règles d'Or pour l'IA

1.  **Strict Respect du Niveau :**
    *   **N1 :** Donne la solution complète et explique chaque ligne. C'est de la démonstration.
    *   **N2 :** Donne la piste, le point de départ, mais laisse l'apprenant écrire le code de la modification.
    *   **N3 :** Agis comme un Chef de Projet ou un Senior Lead : donne des conseils d'architecture, des revues de code, mais n'écris pas le code métier à la place de l'apprenant.

2.  **Cohérence Fil Rouge :**
    *   Toutes les ressources doivent s'inscrire dans le contexte du **Projet Fil Rouge** (Blog/Plateforme de contenu) pour donner du sens à l'apprentissage.

3.  **Encouragement :**
    *   Toujours valoriser la réussite immédiate en N1 (Satisfaction).
    *   Valoriser la compréhension et l'astuce en N2 (Confiance).
    *   Valoriser la qualité professionnelle et l'autonomie en N3.
